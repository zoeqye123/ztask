# zTask — Task Drafting Skill

> **zTask only drafts Tasks; it never executes them.** Activate when the user wants to turn a vague idea into a structured task instruction.

## Activation Conditions

Activate if any of the following applies:

- The user says "draft a task for me" / "write me a task" / "set this up" / "make a plan"
- The user says "I want to do X" / "I need to accomplish Y"
- The user describes a goal and wants it turned into an executable instruction

## Workflow

```
Task Progress:
- [ ] Step 1: Clarify with questions
- [ ] Step 2: Read system context (if needed)
- [ ] Step 3: Generate the Task
- [ ] Step 4: Output and storage advice
```

### Step 1: Clarify with Questions

Ask everything upfront in one pass:

**Must ask:**

- **What?** What exactly is being delivered? ("make it better" is not a Task)
- **Where?** Which directories / projects / files are involved?
- **To what standard?** How do we know it's done?

**Optional:**

- **Any constraints?** Anything off-limits?
- **Any deadline?**
- **Any existing resources?** Materials or references already available?

### Step 2: Read System Context

- If `paths-context.md` exists in the current directory, read it first to understand the user's file structure and help infer the execution folder.
- If it doesn't exist and the task depends on the local environment (e.g., "help me find a suitable directory to run this in"), generate it with the scan script:

```bash
bash ../scripts/scan-paths.sh paths-context.md
```

> The script lives in the zTask repo root at `scripts/scan-paths.sh` (this Skill directory is its child, hence the relative path `../scripts/scan-paths.sh`; if you install this Skill standalone, copy `scripts/` along with it and adjust the path). It scans Git projects, AI tool Skills/MCP setups, and Obsidian Vaults, then outputs `paths-context.md`. Dependencies: bash + python3.

### Step 3: Generate the Task

Generate according to the template below. It **must include**: background, execution context, goals (checkboxes), phased steps, and acceptance criteria.

```markdown
# Task: {Domain} | {Description}

## Background
{Why this task exists}

## Execution Context
| Field | Value |
|-------|-------|
| **📁 Execution folder** | `/path/` |
| **🛠 Related Skills** | `{if any}` |

## Goals
- [ ] {Concrete goal 1}
- [ ] {Concrete goal 2}

## Steps
### Phase 1 · {Phase name}
{Steps...}

## Acceptance Criteria
- [ ] {Verifiable criterion 1}
- [ ] {Verifiable criterion 2}
```

### Step 4: Output

1. Output the complete Task file content (Markdown format)
2. Suggest where to store it (e.g., `~/Obsidian Vault/01 Tasks/Task-xxx.md`)
3. Make it clear that **the next move is the user's** — which AI to run it with and how is not zTask's concern

When finished, say:

```
✅ Task generated. The file content is as shown above.

⚠️ zTask only drafts Tasks; it never executes them.
   The next move is yours — choose which AI to use and how to run it.
```

## Forbidden Actions

- ❌ Generating a Task without clarifying first ("make it better" is not a Task)
- ❌ Spontaneously explaining how to execute after generating
- ❌ Stepping beyond drafting — executing or managing tasks on your own
- ❌ Failing to suggest a storage path
