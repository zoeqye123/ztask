# TaskBrain Agent Skill

> 当用户要求执行 Task，或提到"执行任务"/"完成任务"/"做这个"时，激活此 Skill。

## 激活条件

满足任一即激活：
- 用户粘贴了一个 Task 文件内容
- 用户说"帮我执行这个 Task"/"做这个"
- 用户发送一个 `.md` 文件并要求执行
- 用户说"按 Task 里写的做"

## 执行流程

### 第一步：读取上下文

在执行 Task 之前，必须读取以下文件：

```
paths-context.md          # 当前系统的关键路径（必须先运行 scan-paths.sh 生成）
Task文件.md              # 用户提供的 Task 内容
```

**如果没有 paths-context.md：**
告知用户需要先运行 `scan-paths.sh` 生成路径上下文文件。

### 第二步：解析 Task

从 Task 文件中提取：

1. **执行文件夹**（`📁` 字段）→ 决定 `cwd`
2. **关联 Skills**（`🛠` 字段）→ 决定调用哪些工具
3. **目标** → 明确交付物
4. **执行步骤（Phase）** → 按顺序执行
5. **验收标准** → 执行完毕后对照检查

### 第三步：执行

按照 Phase 分阶段执行：

```
Phase 1 → Phase 2 → Phase 3 ...
```

- 每完成一个 Phase，简要汇报进度
- 遇到阻塞，主动说明卡在哪里、建议如何解决
- 完成后对照验收标准自检

### 第四步：完成与归档

Task 执行完毕后：

1. **更新 Task 文件的 signpost 行**：
   ```
   - [ ] → - [x]
   添加 ✅ 完成日期
   ```
2. **告知用户**：Task 完成后 signpost 行已更新
3. **归档提示**：告知用户将文件移入 `history/` 目录

## 核心原则

1. **先读 paths-context.md** — 不知道文件在哪就无法执行
2. **执行文件夹必须正确** — 决定 AI 读写文件的位置
3. **按 Phase 顺序执行** — 不跳步，不省略
4. **交付物写磁盘** — 不要只输出在对话里，要写入执行文件夹
5. **完成后更新 signpost 行** — 这是 Task 完成状态的唯一来源

## 禁止事项

- ❌ 不读 paths-context.md 就执行
- ❌ 不在指定目录执行
- ❌ 只输出在对话里，不写文件
- ❌ 跳过 Phase 步骤
- ❌ 不更新 signpost 行就结束

## 文件路径参考

| 文件 | 路径 |
|------|------|
| 路径上下文 | `paths-context.md`（同目录下） |
| Task 文件 | 用户提供，通常在 `~/Obsidian Vault/01 Tasks/` |
| 归档目录 | `~/Obsidian Vault/01 Tasks/history/` |
